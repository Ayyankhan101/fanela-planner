# Phase 0 — Data Contract & Fixture Inventory

**Status: DECIDED 2026-09-30 — no data exists yet; data arrives later through the self-service import screen (Phase 3).** This document is the contract that screen enforces, plus the synthetic-fixture inventory used for development and UAT until real data appears.

---

## 1. Accepted input shapes

The import screen accepts exactly one file (JSON) and detects its shape:

| Shape | Detection | Accept? |
|---|---|---|
| **A — Full localStorage dump** (preferred) | object whose values are all strings; contains a planner-state key | ☑ accept |
| **B — v11 state object** | top-level `jobs` array + (`schemaVersion` or `customers` or `products`) | ☑ accept |
| **C — raw jobs array** | top-level JSON array | ☑ accept (limited) |
| **D — Backup-button export** | `{version, exportedAt, jobs}` without catalogs/history | ☒ **reject with message** |

Rejection message for D (finding F9): *"This file contains jobs only — stock history and audit log are missing. Export a full localStorage dump (see data-quality instructions)."*

### What shape A must contain

| Key | Entity | Missing ⇒ |
|---|---|---|
| `fanela_internal_production_planner_ops_v11` (or first hit among 12 legacy keys, L180) | state | reject |
| state.`customers` | customer master | rebuild from jobs via `linkCatalogs` rules; warn |
| state.`products` | catalog | rebuild from lines; warn |
| state.`stockEvents` | stock history | **hard reject** (not rebuildable) |
| state.`operationsEvents` | operational audit | **hard reject** (not rebuildable) |
| `…_accounts` | role mapping only | optional; passwords discarded |

Fallback key if state key lost: `…_ops_v11_before_import` (L475, full snapshot incl. events).

### Version limits
- `schemaVersion` absent or ≤ 3 → accept (legacy shapes run through `migrateState` rules or map per `06`).
- `schemaVersion` > 3 → reject ("file from newer prototype").

## 2. Validation rules (import preflight — same as `analyze-backup.mjs`)

Every issue below appears in the preview as *create / skip / error* rows before confirm:

| Check | Severity |
|---|---|
| Duplicate job numbers | error (block those rows) |
| Duplicate customers (case-insensitive name) | warn (merge candidate) |
| Missing/blank job number | error |
| Jobs referencing missing customer | warn (catalog rebuild) |
| Lines without SKU | warn |
| Invalid date fields (`YYYY-MM-DD`) | error per row (row skipped) |
| Non-integer quantities | error per row; **negative received = valid** (rule J4) |
| Terminal swatch attempts present | info — must migrate bit-identical, immutable |
| Shipments without state enum | info — state inferred per `06 §4`, listed for review |
| Blank `screensRequired` (null) | info — migrates as NULL (rule G4) |

**Import rules (decided defaults):** dedupe on `job_number` + `SKU`; re-import of same file allowed — existing rows skipped, new rows created (rule E3); imported artwork starts `Draft`; only Admin/Ops may import and may waive swatch (E6); every import writes an `import_batches` row + keeps the original file.

## 3. Preview → confirm → execute (spec §5 import pipeline)

```text
Upload → Parse (shape detect) → Validate (§2) → Preview (creates/skips/errors counts)
  → Confirm (typed confirmation for large sets) → Execute (single transaction per batch)
  → Audit (import batch row, per-entity audit events) → Result (summary + downloadable error list)
```
Cancel any time before Execute = no writes.
